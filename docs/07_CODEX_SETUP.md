# 최초 세팅 / 기능 확인

## 이미 준비된 상태
`AGENTS.md`, 상세 마스터, 로컬 지침 스킬, 원본 이미지, 출력 폴더, 무결성 검사기가 포함되어 있다.
앱을 개발할 필요 없다. Node/npm/웹서버/Unity 프로젝트 생성은 이 작업 범위 밖이다.

## Codex가 최초 요청에서 확인할 것
1. 현재 작업 디렉터리가 AGENTS.md·project.json이 있는 폴더인지 확인한다.
2. 기존 전역/상위/하위 AGENTS.override.md 등이 충돌하는지 확인하되 임의 수정·삭제하지 않는다.
3. `python3 scripts/validate_project.py` 실행. Python이 없으면 파일 확인을 직접 수행하고 설치를 강제하지 않는다.
4. `.agents/skills/game-env-art/SKILL.md`를 읽는다. 로컬 스킬이 자동 탐지되는지 확인하되 미탐지라도 직접 읽어 실행 가능하다.
5. 현재 실제 도구 목록에서 내장 이미지 생성/공식 imagegen 스킬을 확인하고 해당 설명을 읽는다.
6. 원본 PNG를 열어 볼 수 있는지, 도구에 실제 이미지 참조를 제공할 수 있는지 확인한다.
7. 쓰기 권한과 출력 아티팩트 처리 방식을 확인한 뒤 `state/setup_status.json`을 실제 관찰 내용으로 갱신한다.
8. 사용자가 생성/테스트를 요청했다면 준비 후 실제 생성한다. 분석·검수·마스터 갱신 요청은 예시를 읽어도 생성하지 않는다. 환경 문제만 있으면 필요한 최소 조치만 보고한다.

## 기본 경로
OpenAI 공식 이미지 생성 안내는 내장 생성과 `$imagegen` 명시 호출을 설명한다.
내장 생성은 Codex 사용량 범위와 관련되고, API 사용은 별도 인증/과금 경로이다.
패키지는 버전/계정의 실제 가용성을 보장하지 않는다. 런타임에서 확인한다.

### API 키를 요구받았을 때
공식 스킬이나 클라이언트에 따라 API 기반 경로가 선택될 수 있다.
먼저 내장 경로가 있는지 확인하고, API만 가능하면 이유·필요 설정·별도 과금 여부를 알려 동의를 받는다.
키를 문서에 붙여넣거나 ZIP/기록/로그에 넣지 않는다. 이미 키가 있어도 임의 사용하지 않는다.

### 스킬이 목록에 보이지 않을 때
문서 파일은 자동 발견과 관계없이 직접 읽을 수 있다.
현재 폴더가 맞는지 확인하고 필요하면 그 폴더에서 새 세션을 시작한다.
앱 UI와 로컬 스킬 자동 탐지는 버전에 따라 달라질 수 있다. 전역 config를 자동 덮어쓰지 않는다.
공식 사용법/업데이트 확인이 필요한 경우 docs/09_SOURCES.md의 공식 문서를 확인한다.

### 원본을 읽지만 이미지 도구에 전달할 수 없을 때
원본을 열어 본 것과 생성 입력에 포함한 것을 구분해 기록한다.
핵심 참조를 지원되는 첨부 방식으로 연결하는 최소 조치를 안내한다.
“파일이 폴더에 있으니 이미지 모델도 당연히 봤다”고 가정하지 않는다.

### 결과가 나오지만 저장·검수가 다음 턴에만 가능한 때
도구가 반환한 실제 이미지 위치를 보존한다. 파일 접근이 가능한 다음 턴에 저장/검수한다.
`검수해줘`는 추가 이미지 호출 없이 현재 결과를 검사하는 요청으로 처리한다.

## 하지 않을 설정
전역 `~/.codex/config.toml`, `~/.codex/AGENTS.md`, 시스템 권한, 결제, 클라우드 연결을 바꾸지 않는다.
이 프로젝트의 Git 저장소·원격 저장소·공개 업로드를 자동 생성하지 않는다. Git이 필요하다고 실제 확인된 경우 먼저 안내한다.
이 폴더는 코드 빌드가 없어도 사용할 수 있는 로컬 문서+참조 작업 폴더다.

## v2.8 / 실행1.9 기록 연결 확인

`project.json`은 프로젝트 운영 데이터이며 내장 모델 설정 파일이 아니다. native 도구에 없는 model/quality/seed/참조 가중치·영역 마스크·추론 옵션을 만들어 넣지 않는다. Ultra 선택과 내부 이미지 렌더 설정의 연결은 노출된 근거가 없으면 미확인이다. 이 작업 폴더에서 전역 설정을 변경하지 않는다.

`state/setup_status.json`은 확인한 날짜·호스트의 관찰이다. 다른 컴퓨터에서 Git을 받아 열었을 때 새 환경의 가용성으로 간주하지 않고 위 절차를 다시 확인한다. 로컬 파일을 읽고 쓴 사실과 실제 생성/참조 전달을 새로 시험한 사실을 구분한다.

새 생성 run은 `templates/requirements.json`의 원장을 채우고 다음 단계를 적용한다.

```bash
python3 scripts/validate_run.py --run outputs/<run> --stage preflight
python3 scripts/validate_run.py --run outputs/<run> --stage review
python3 scripts/validate_run.py --run outputs/<run> --stage selection
```

표준 라이브러리만 사용하며 네트워크·API·모델 호출은 없다. 사전 단계는 원장·실제 전달 예정 문장/참조 연결, 검수/선택 단계는 실제 입력/결과/관찰/후보 비교 연결을 확인한다. 기록 검사 PASS가 그림을 통과시키지 않는다. 실제 이미지 검수는06을 따르고, 구조만 통과해도 다른 필수 조건이 실패하면 전체 완료로 표시하지 않는다. 과거 run은 소급 변환하지 않는다.
