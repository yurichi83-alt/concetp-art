# 기록 검증기 독립 계약 검토 — 2026-09-12

`scripts/validate_run.py`, `scripts/test_validate_run.py`, `templates/requirements.json`, `docs/05_GENERATION_RULES.md`, `project.run_validation_policy`를 대조했다. 코드 작성 에이전트와 별도로 합성 fixture를 변형해 **보강이 필요한 다섯 항목을 재현했고, 담당자의 수정 후 모두 해소됨을 확인했다.** 최종45개 테스트와 독립 여섯 재현을 통과했다. 이번 검토 범위에서 미해결 중대한 계약 불일치는 발견하지 못했다. 아래 최초 발견 기록과 후속 확인은 구분해 보존한다.

검토 중 기존 38개 테스트는 모두 통과했다. 추가 검사는 기존 `RunValidationTests`를 일시 디렉터리에서 실행했다. 이미지 파일은 테스트용 임의 바이트이며 실제 이미지 검수·생성 근거가 아니다. 코드·템플릿·기존 run·Git은 변경하지 않았고 이 문서만 저장했다.

## 재현한 문제

| 항목 | 재현 | 최초 결과 | 영향과 필요한 보강 |
|---|---|---|---|
| 1. 알려진 보정 전 후보가 선택 비교에서 빠짐 | `make_edit()` 후 `selection.considered_candidates`에 현재 결과 하나만 유지 | `RECORD PASS / candidate_pass` | `comparison.baseline`을 알고도 후보 비교에서 빠뜨릴 수 있다. 적어도 명시된 기준 후보를 선택 비교에 포함하고, 다른 후보가 있다면 같은 요청/시안의 명시 목록에 빠짐없이 연결해야 한다. |
| 2. 현재 이미지를 자기 자신의 수정 전 이미지로 사용 | `comparison.baseline.image_path`와 해시를 현재 candidate로 교체 | `RECORD PASS / candidate_pass` | 수정 전후 보존을 실제로 대조하지 않은 기록이 R03 통과와 공존한다. 기준 경로가 현재 결과와 같은지 확인해야 한다. 정상적인 무변경 결과 가능성을 고려하면 서로 다른 원본 파일의 해시 동일만으로 모든 편집을 거절해서는 안 된다. |
| 3. 상시 필수 정사영을 일반 N/A 사유로 제거 | C04 요구와 check를 `applicable:false`, `NOT_APPLICABLE`, “Not applied to this run.”으로 변경 | `RECORD PASS / candidate_pass` | 필수 정사영을 제외하는 명시 사용자 변경 기록 없이 전체 완료가 된다. 일반 미해당 항목과 사용자 예외가 필요한 상시 요건을 구분하고, 예외에는 해당 요청 근거를 연결해야 한다. 문장의 참·거짓까지 자동 판정한다는 뜻은 아니다. |
| 4. 정직한 미검수 전달을 거절 | 모든 적용 관찰을 `NOT_REVIEWED`, 후보/선택 상태를 `not_reviewed`, 열람을 `false`로 기록하고 미검수 사유·중단 사유 기재 | `RECORD FAIL / not_reviewed`, 오류 `selection: candidate not actually opened` | 문서는 관찰 불가·호스트 중단 시 미검수 전달을 허용하지만 선택 검증은 무조건 열람을 요구한다. 미검수 전달은 합격 주장 없이 보존하도록 허용하고 실제 PASS/FAIL/UNCERTAIN 판단에는 열람을 요구해야 한다. |
| 5. 정상 도구 입력/명시 편집을 문서 계약보다 좁게 제한 | (a) `num_last_images_to_include:1`과 대화 첨부 증거를 기록하되 로컬 경로가 없는 첨부 사용. (b) 사용자가 명시한 master03 이미지의 새 편집본을 `edit_target`으로 기록 | (a) `missing path`·`sha256 required`·`missing path`, (b) `role exceeds approved catalog scope` | (a) 현재 내장 도구의 recent 방식은 로컬 경로 없는 대상에 쓰는 정상 방식이다. 실제 로컬 파일과 대화 이미지 증거를 구분해야 한다. (b) 생성 참조의 승인 역할과 명시된 편집 대상의 역할을 구분해야 한다. 원본 덮어쓰기나 기하 마스터 승격을 허용하자는 뜻은 아니다. |

위 재현에서 선택 상태와 `result.json`/최종 manifest 상태를 서로 일치시켰다. 따라서 문제 1~3은 단순한 전체 상태 문자열 불일치 검사로는 잡히지 않았고, 문제 4~5는 정직한 입력이 더 강한 조건에 막힌 경우다.

## 확인한 정상 범위

- 실제 프롬프트와 저장 문자열, 요건별 실제 구절, 참조 순서·개수·파일 해시와 원장 연결을 검사한다.
- C/L/S/W/R의 check ID 누락, 실패 요건을 PASS check로 덮기, 관찰 전 PASS, 미열람 결과의 관찰 판정, 표면의 긍정/금지 증거 누락, 결과/선택/manifest 상태 불일치를 거절한다.
- `critical:false`로 UNCERTAIN을 전체 합격에서 숨길 수 없다.
- 실제 S03 실패를 `needs_revision`으로 유지하고 이유를 남긴 전달은 `RECORD PASS / image QA needs_revision`으로 구분한다. 기록 검사 PASS가 시각 합격은 아니라는 project 정책과 맞는다.
- 최근 이미지 선택의5장 상한을 경로 입력 한도로 자동 적용하지 않으며 과거 run을 소급 스캔·수정하지 않는다.
- 수정 비교의 `uncertain`을 R03 PASS로 두는 경로는 작성 담당자가 검토 중 보강했으며 기존 38개 테스트에 포함돼 통과했다.

## 자동 검증의 한계

이 검증기는 실제 픽셀을 보거나 시각 관찰의 진실성·프롬프트 의미의 충분함·후보 선택의 미관 판단을 증명하지 않는다. 의미 없는 문장을 증거처럼 작성하면 그 의미를 자동 판별할 수 없다는 한계는 문서에 공개되어 있다. 이번 발견은 이런 한계와 별도로 **기록만으로 확인 가능한 자기비교·상태/권한/입력 방식의 불일치**를 대상으로 했다.

다른 후보의 전체 시각 품질, 표면별 확대 판독, 구조·아트·요청의 독립 판단은05/06에 따른 실제 검수를 계속 필요로 한다. 전체 통과본이 없으면 최신 미달 결과를 정직하게 전달할 수 있지만, 이를 `candidate_pass` 또는 전체 완료로 바꾸면 안 된다.

정책상 비교 범위는 같은 요청/시안의 전체 보정 연쇄다. 검증기는 자동으로 과거 폴더를 탐색하지 않으며 **명시된 후보·기준·알려진 부모의 연결만 확인한다.** 기록 어디에도 적지 않은 실제 후보까지 모두 발견했다거나 전체 후보 목록의 완전성을 인증한다고 보고해서는 안 된다. 문제1은 이 한계와 별개로 이미 기록된 baseline조차 선택 비교에서 누락할 수 있던 경우다.

## 수정 후 재검증

작성 담당자가 보강한 최종 코드에서 테스트45개가 모두 통과했다. 최초 다섯 항목을 여섯 재현으로 나누어 최종 코드에 독립 재실행한 결과도 아래와 같이 기대한 동작을 확인했다.

| 독립 재현 | 수정 후 기록 판정 | 확인 |
|---|---|---|
| 알려진 baseline을 선택 후보에서 누락 | FAIL | `known correction baseline missing`으로 거절 |
| 현재 이미지를 자기 baseline으로 사용 | FAIL | `baseline cannot be the current candidate itself`로 거절 |
| C04를 일반 N/A 사유만으로 제거 | FAIL | 현재 사용자 예외의 출처·실제 인용을 요구 |
| 실제 미열람을 정직하게 기록한 전달 | PASS / image QA `not_reviewed` | 미검수 상태를 합격으로 바꾸지 않고 보존 |
| 로컬 경로가 없는 대화 이미지 참조 | PASS | recent 방식과 대화 이미지 증거로 기록; 미확인 로컬 해시를 만들지 않음 |
| 사용자가 명시한 master03의 별도 편집본 | PASS | 요청 출처·인용·증거를 갖춘 편집 대상으로 허용 |

거절된 앞3건은 진단 필드에 계산 중인 `candidate_pass`가 남더라도 최상위 `record_status:FAIL` 및 비정상 종료 코드가 통과를 막는다. 그 진단 문자열만으로 전체 합격을 보고하면 안 된다.

최종 재검증 대상 SHA-256:

- 검증기: `92cdcdcc09fcbfabf2404e3d038c2f02ee1d9558d7ebb14cbf8354adb1ced486`
- 테스트: `c1b87c8c8b55c928c8f1b647d880904a8761f29a61265551eccecb1b53ecdce8`
- 요구사항 템플릿: `945eb4492b041db9e9e20dc446ce7c6efe22e2a8625e1fc2fff7dde8153d803d`

작성 담당자가 추가로 확인한 '로컬 경로 없는 대화 이미지 자체를 편집 기준으로 쓰는 경우'도45번째 테스트에서 검증했다. 로컬 경로·해시는 null로 유지하고, baseline과 후보가 실제 검토한 편집 대상의 `reference_id` 및 동일한 대화 이미지 증거로 연결되면 통과한다. 다른 미기록 대화 이미지를 기준으로 바꾸면 거절된다. 이 테스트도 실제 이미지 생성이나 시각 QA를 수행한 것은 아니다.
