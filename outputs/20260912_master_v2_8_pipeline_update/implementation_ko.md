## 자동 보정과 완료

이번 승인으로 **생성/편집 요청에서 관찰한 명시 마스터·현재 사용자 요건의 실패**를 C/L뿐 아니라 S/W/R까지 자동 보정 대상으로 명확히 확대했다. 구조만 통과해도 다른 적용 필수 조건이 실패하면 전체 `needs_revision`이다. 모든 적용 조건과 QA가 실제 이미지 근거로 통과해야 `candidate_pass`이며 사용자 마스터 승인과는 다르다.

단순 취향 탐색의 추가 변형은 자동 보정이 아니다. 분석·검수·마스터 갱신 요청 자체로 이미지를 생성하지 않는다. 보정 중단 한계에 도달하면 남은 실패/불확실과 선택 이유를 기록한다. 미달 전달본을 final에 보관할 수 있으나 전체 완료로 부르지 않는다.

## 파일과 기록 검사

- `validate_project.py`: 파일 존재, 참조 해시/역할/승인, 현재 버전, 원장/운영 정책 연결을 확인한다.
- `validate_run.py`: 새 run의 preflight/review/selection 단계에서 실제 구절·입력·참조·해시·관찰·후보/선택 기록의 일치를 확인한다. 과거 run을 자동 탐색하거나 소급 수정하지 않는다.
- `test_validate_run.py`: 정상 기록과 의도적인 누락/허위 승격/후퇴/경로 오류를 임시 fixture로 검사한다. 생성 도구·네트워크를 호출하지 않는다.

검사기는 이미지 자체를 읽고 미술적으로 판단하지 않으며, 관찰 문장을 사람이 실제로 보았는지나 문구가 충분히 의미를 전달하는지를 입증하지 않는다. 기록 검사 PASS는 그림 PASS와 다르며 정직한 미달 전달의 기록도 PASS할 수 있다. 실제 생성 호출을 강제 차단하는 모델 엔진이 아니라 Codex 실행 스킬이 따르는 단계별 기록 검사다.
