# 생성 작업과 최종 전달본

- 날짜별 작업 폴더: 원본 이미지, 모든 시도, 브리프·프롬프트·참조·구조안·검수 기록을 보존합니다.
- `final/`: 요청별 최종 전달 이미지만 모은 폴더입니다. 이미지 파일만 들어갑니다.
- [FINAL_INDEX.md](FINAL_INDEX.md): 이미지·원본 작업·검수 상태를 연결한 목록입니다.
- `final_manifest.json`: 선택 근거·원본 상대경로·복사 이름·SHA-256 및 과거 파일 제외 사유를 기록합니다.

## 선택 기준

자동 보정 연쇄에서는 실제 최종 전달 대상으로 선택한 이미지만 복사합니다. 파일명의 final, 생성 시각, QA PASS만으로 선택하지 않습니다. delivery/result와 전달 기록이 우선입니다. 여러 장 요청은 각 시안을 포함하며, 사용자 별도 편집 요청은 각 요청의 전달본으로 보존합니다.

검수 보류나 결함이 남은 상태로 전달했던 결과도 상태를 유지해 보관합니다. 이 폴더는 합격작/승인작/새 마스터 목록이 아닙니다. run 원본과 이전 검수는 수정·삭제하지 않습니다.

## 앞으로 저장하는 방법

1. 생성·보정·검수를 마치고 최종 원본을 해당 run에 저장합니다.
2. final_manifest.json의 images에 source(저장소 상대경로), filename(날짜·장면·시안을 구분하는 고유 이름), qa_status, selection_reason, evidence(전달/결과/검수 기록 경로)를 등록합니다. 최초 sha256과 bytes는 생략해도 됩니다.
3. 저장소 루트에서 `python scripts/collect_final_images.py`를 실행합니다. 명시적으로 선택한 원본만 복사하고 해시·목록을 갱신합니다.
4. `python scripts/collect_final_images.py --verify`로 바이트 일치·중복·누락·불필요 파일을 확인합니다.

같은 요청의 선택본을 교체하면 목록과 기존 모음 사본을 함께 정리하되 run 원본·중간본은 유지합니다. 스크립트는 충돌 파일을 임의로 덮어쓰거나 삭제하지 않습니다. 최신 PNG를 자동 추측하여 수집하지 않습니다.
