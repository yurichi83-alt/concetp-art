# Generation Execution Rules v1.1

> 기준 관계: 원본 마스터 01~04와 원본 레퍼런스 19장이 상위 기준이다. Little Devil Inside 아트 표현(세계관 제외)과 Salvage Cyberpunk 세계관은 고정한다. A-01/A-02는 그 기준으로 생성된 결과 중 사용자 선호 예시이며 마스터를 대체하지 않는다. 상세: `docs/10_CURRENT_REFERENCES.md`.

## 0. 이 워크플로의 범위
이 프로젝트의 짧은 장소/시간/소재 요청은 실제 **배경 이미지 생성** 요청이다.
이미지 생성 앱을 만들거나 글 프롬프트만 제공하고 끝내지 않는다.
`검수만`, `기준 보여줘`, `파일 정리`는 생성 요청이 아니다.
상위 시스템·호스트·도구의 실제 계약을 지키며 여기에 없는 API 옵션을 지어내지 않는다.

## 1. 변경분 해석
`docs/08_COMMANDS.md`에 따라 장소·시간대·색·소재·장수를 파악한다.
사용자가 말하지 않은 필수 공간/스타일 조건은 유지한다. 예외는 이번 장면과 영구 변경을 구분한다.
미정 장면 세부는 마스터에 맞게 선택하고 기록한다. 사소한 미정 요소마다 질문하지 않는다.

## 2. 원본 준비
`refs/manifest.json`의 역할을 확인하고 해당 이미지를 실제로 열어 본다.
기본 구도 입력은 M02-01(연결 관계), M01-01(카메라와 단면).
기본 표현 입력은 M03-10. 실내/야간/실외 보조 스타일 한 장을 필요에 따라 고른다.
M04-02 또는 M04-04 등은 세계관 형태의 보조 원본이며, 캐릭터와 재질 밀도는 복사하지 않는다.
A-01/A-02는 원하는 결과 인상의 보조 참조다. 장면에 맞춰 추가하되 원본 마스터보다 우선하지 않는다. 입력 장수 제한이 있으면 원본 핵심 구도·공간·아트 참조를 우선한다.
한꺼번에 모든 19장을 넣지 말고 실제 도구가 지원하는 범위에서 작은 참조 세트를 고른다.
입력 장수가 제한되면 01·02의 공간과 03의 표현을 우선하며, 04의 디자인 언어는 텍스트에 정확히 유지한다.

**실제 참조 전달:** 도구가 파일/이미지 인자를 받으면 그 스키마에 맞게 파일을 전달한다.
현재 대화의 이미지만 받는 환경이면 그 환경이 지원하는 첨부/시각 컨텍스트 방식으로 원본을 제공한다.
경로를 프롬프트 문장에 쓰거나 Codex가 이미지를 열어 본 것과 이미지 모델에 전달된 것은 다르다.
전달할 수 없으면 파일 기반 참조가 불가능함을 알리고, 핵심 이미지를 첨부하는 등 지원되는 방법을 요청한다.
파일 전달이 안 되는데 몰래 텍스트 전용으로 같은 결과가 보장되는 것처럼 진행하지 않는다.
`review_only/`는 기본 입력 금지. 웹에서 임의의 대체 이미지를 찾아 마스터를 바꾸지 않는다.

## 3. 도구 확인과 비용 범위
세션에서 사용 가능한 내장 이미지 생성 또는 공식 imagegen 스킬의 설명을 먼저 확인한다.
내장 기능 우선. 별도 API 경로만 있으면 비용·키 필요 여부를 설명하고 사용자의 동의를 받은 후 사용한다.
기존 환경에 API 키가 있어도 그 존재만으로 사용 동의로 취급하지 않는다. 키를 출력·기록하지 않는다.
API 모델명·버전·가격은 하드코딩하지 않는다. 전역 설정·플러그인 설치·추가 구매를 임의로 하지 않는다.
기능이 없으면 프롬프트/준비 상태를 저장하고 장애를 보고한다. 생성했다고 말하지 않는다.

## 4. 실제 생성 사양
- 한 결과당 단독 장면 하나. 요청 2장이면 파일 2개. 분할 화면/비교 시트는 사용자가 원할 때만.
- 베이스 전체와 앞쪽 두 측면 단면이 보이는 사선 하이앵글. 크롭을 방지할 주변 여유를 둔다.
- 뒤쪽 두 차단 경계에 출구 한 개씩, 정확히 두 개. 둘 다 보이고 접근 가능.
- 중앙에 넓고 연속된 빈 전투 바닥. 외곽 물체도 출구를 막지 않는다.
- 모델링 큰 면, 선택적 손상, 저밀도 3D 재질. “high quality”를 “high detail”로 자동 확장하지 않는다.
- 04의 회수·개조 첨단기술 적용. 03의 세계관이나 01의 네온 테마는 복사하지 않는다.
- 글자·번호·슬로건·화살표·UI는 요청 없으면 추가하지 않는다. 간판이 필요하면 제한적으로 사용한다.
- 인물/몬스터는 요청이 없는 배경 시안에 자동 삽입하지 않는다.
- 장식이 공간 규칙과 충돌하면 장식을 줄인다. 카메라·출구·단면·중앙을 생략하지 않는다.

작업용 화면 비율은 원본처럼 전체 베이스가 읽히는 비율을 고른다(예: 4:3 또는 1:1).
지원하지 않는 픽셀 옵션을 가정하지 않는다. 비율은 제안된 출력 선택이며 마스터의 고정 치수가 아니다.

## 5. 생성 전 기록
`outputs/<local_timestamp>_<scene_slug>/`를 고유하게 만든다(기존 폴더 덮어쓰기 금지).
- `brief.md`: 장면 해석, 마스터 버전, 구조 계획, 사용자가 보낸 원문, 컴파일한 아트 지시.
- `references.json`: 검토한 원본과 실제 도구 입력으로 전달한 원본, 역할, 순서/전달 상태.
- `preflight.md`: 필수 조건이 계획에 포함되는지, 도구·파일 접근·요청 장수 확인.
이 브리프는 **의도한 생성 지시의 기록**이지 비공개 내부 프롬프트 원문을 확보했다는 뜻이 아니다.

## 6. 호출과 저장
요청 장수는 최종 전달할 장수다. 사용자가 2026-09-09에 승인한 구조 오류 자동 보정에 따라, 실제 검수에서 구조 오류가 발견되면 재확인 없이 수정·재생성한다.
- 대상: 출구 수·위치·가시성, 뒤쪽 경계, 건물 배치/각도와 지면 정렬, 중앙·출구 동선, 전체 프레이밍과 바닥 단면.
- 수정 전에 실제 오류와 유지할 요소를 기록한다. 바닥 연결이나 건물 배치 자체가 잘못되면 기존 이미지를 그대로 보존하려 하지 말고 M01/M02에 맞춰 재구성한다.
- 매 결과를 실제로 열어 구조를 검수한다. 구조 통과 시 최종 한 장으로 전달하고 추가 변형을 중단한다.
- 자동 보정 이력은 각각 고유 run에 입력·지시·결과·검수와 이전 run 연결을 보존한다. 잘못된 결과는 삭제/덮어쓰지 않는다.
- 스타일·색·손상 밀도에 대한 취향 차이만으로 자동 변형을 늘리지 않는다. 구조 보정 중 기존 아트/세계관/현재 키워드는 유지한다.
- 관찰 불가, 도구 오류/한도, 별도 과금 API·설치·권한 확대 필요, 사용자의 중지, 또는 동일 오류가 반복되고 새로운 수정 전략도 없는 상황에서는 추가 호출을 멈추고 상태를 설명한다. 같은 지시를 무작정 반복하지 않는다.
- 이 승인은 프로젝트 내 내장 도구의 구조 수정에 한정된다. 별도 API·설치·전역 설정·마스터 자동 승격 권한은 포함하지 않는다.
도구 반환의 실제 파일/아티팩트에 접근 가능하면 원본 형식 그대로 같은 run에 저장한다.
PNG가 아닌 파일을 확장자만 PNG로 바꾸지 않는다. 존재하지 않는 경로/다운로드 링크를 만들지 않는다.
도구가 결과를 UI에만 제공하면 그 사실과 접근 가능 범위를 기록한다. 결과 복사는 다음 턴에 가능할 수 있다.
이미지 생성 후 즉시 응답을 종료해야 하는 호스트에서는 그 규칙을 따르고, 저장/QA는 다음 턴에 진행한다.

## 7. QA와 전달
실제 결과를 열 수 있는 경우 `docs/06_QA.md`의 기준으로 관찰하고 `review.md`에 기록한다.
열 수 없거나 후처리가 막혔으면 `not_reviewed`. 정확한 높이는 `requires_3d_validation`.
결과를 전달하되 결함을 숨기지 않는다. 검수 합격과 사용자의 아트 승인을 구분한다.
구조 오류는 위의 상시 승인에 따라 실패한 부분과 유지 부분을 나눠 다음 run에서 수정한다. 구조 외 추가 생성은 현재 사용자 요청 범위를 따른다.
사용자 승인 없이는 master·refs·approved ledger를 성공 결과에 맞춰 바꾸지 않는다.
