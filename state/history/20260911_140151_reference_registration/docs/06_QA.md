## 검사 순서
기본 입체 → 공통 투영/지붕 면 정합 → 건물 직교 경계 → 바닥/경계 접합 → 두 기능 출구의 상태별 동선 → 해당 내부 동선 → 스타일 → 세계관 → 개별 요청.
구조안의 사전 검사와 실제 최종 이미지 검사를 따로 기록한다. 계획 PASS, 프롬프트의 규칙, 단순 경계상자(AABB) 무충돌은 최종 PASS의 근거가 아니다. 저장된 실제 이미지를 열고 아래 필수 정사영 대조를 수행한다. 프롬프트에 orthographic이 있다는 사실만으로 최종 정사영을 PASS 처리하지 않는다.
이미지를 열 수 없으면 `NOT_REVIEWED`; 애매하면 `UNCERTAIN`으로 남긴다.

출구 위치는 각 면의 중앙·중간·끝 모두 가능하며 고정 좌표나 강제 교대 순서가 아니다. 건물 입구/내부 전환, 건물 사이 골목과 개폐 철문, 계단/시설 통로, 지하 주차장 램프 등의 기능을 판정한다. 모든 출구에 독립 문틀과 문턱 너머의 노출 바닥을 요구하지 않는다. 닫힌 출구는 접근 공간·개방 장치의 여유·클리어 후 연결 계획을 확인하고, 열린 출구는 실제 보이는 연결 동선의 장애물을 확인한다. 전환 대상인 건물 내부 전체가 숨겨졌다는 이유만으로 실패시키지는 않되 입구 규모/접근/기능이 모호하면 UNCERTAIN이다. 지정 후방 출구의 지하 진입과 전면 토층 절개의 제3출구화를 구분한다.

높이 약 6.5m, 정확한 통로 폭, 실제 플레이어/콜라이더 통과는 3D 치수 검사 대상이다.
이미지 검수에서 수치 적합으로 단정하지 않는다. S04도 3면도 정합·AI 메시 품질·UV/재질맵 검증을 뜻하지 않는다. 계획 의도와 확실히 과도한 높이 여부만 기록한다. 향후 정확한 모델링의 기하 기준은 고정한 3D 블록아웃·카메라이며 생성 2D 이미지는 외관/재질/조명 탐색 자료다. 이 구분만으로 지금 별도 메시·3면도 제작을 시작하지 않는다.
출구 수는 문 개수가 아닌 지정 이동 기능으로 세며, 계획과 실제 관찰을 구분한다. 가려지거나 기능이 애매하면 정확히 두 개라고 확정하지 않는다. 닫힌 상태의 개방 후 동작을 한 장의 이미지로 실증했다고 주장하지 않는다.

## 최종 이미지의 기하 근거 — v2.5
근거 절차: master_update_20260910_v2_4; 필수 정사영 보강: master_update_20260911_v2_5. 검수 시작 시 원본 이미지 경로·해상도, 구조안 경로/사전 상태, 필수 정사영과 장면 카메라 선택을 기록한다. 축을 보여주는 구조 안내는 비교 기준이며 모델이 그 기하를 그대로 보존했다는 보증이 아니다.

1. **비교선 분류:** 베이스 X/Y 상단과 하단, 축을 따르는 포장, 각 건물의 보이는 기단·수평 벽 상단·해당 방향의 수평 지붕선을 고른다. 왜 같은 3D 방향의 선쌍인지 적는다. 쿼터뷰 사선 자체는 정상이며 화면 90도를 요구하지 않는다. 경사 지붕선·경사진 용마루/처마·차양 끝·그림자·회전 소품을 잘못된 수평 비교선으로 섞지 않는다. 지붕 면의 시작/끝·용마루/골·처마·벽 상단·장비 받침은 별도 연결/지지 검사(C04/L05)로 남긴다.
2. **정투영/평행투영 대조:** 같은 방향 선군의 평행성을 베이스 상하단에서 포장·기단·벽 상단·수평 지붕선으로 이어 비교한다. 베이스의 보이는 상하 대응점은 공통 수직축을 따르고, 같은 깊이만큼 내린 벡터는 방향과 화면 길이가 같아야 한다. 건물마다 다른 선 방향이나 가까운 모서리만 커지는 대응 벡터를 선택한 계획과 대조한다.
3. **원근 혼입 판정:** 같은 실제 길이/방향의 화면 길이가 깊이에 따라 변하거나 같은 방향 선군이 수렴하면 정사영 불일치로 C04 FAIL을 기록한다. 단면의 상하 대응 모순은 C02에도 기록한다. 일관된 약한 투시라 해도 합격 대안이 아니다. 회전·경사·실제 치수 차이를 거리 효과로 혼동하지 않고, 비교 근거가 부족하면 UNCERTAIN으로 남긴다.
4. **접촉 경계와 가림:** 구조안의 외곽선 선분/축과 최종 기단·접촉 외벽을 비교한다. 상단의 투영 불일치(C04)와 실제 지상 평면의 회전(L07)은 별개다. 기단이 가려진 상태에서 지붕/차양선만으로 평면 회전각을 확정하지 않는다. L07의 중요한 접촉 경계를 확인하지 못하면 UNCERTAIN이며 계획 PASS/AABB 무충돌로 보충하지 않는다. 명확한 다른 선군 모순은 그 항목의 FAIL로 유지한다.
5. **바닥 인상의 원인 분리:** 볼록하게 읽힘, 화면상 외곽선의 굽음, 상하 대응/원근 변화, 명암과 포장 패턴을 나눠 기록한다. 직선 외곽만으로 전체 평면을 보증하지 않고, 볼록한 인상만으로 물리적인 3D 곡률을 확정하지 않는다. 관찰한 투영 모순은 C02/C04에, 실제 확인한 기본 형상 문제는 C03에 근거를 적는다.

`templates/review.md`의 **선쌍 근거 표와 상하 대응 표**를 채운다. 원본 해상도의 좌상단을 (0,0), 오른쪽 +x, 아래쪽 +y로 두고 선분 끝점/대응점 위치를 남겨 재검토 가능하게 한다. 정밀한 전 픽셀 계측은 요구하지 않는다. 장면을 판단할 대표 선쌍을 두 축과 각 건물/높이에서 선택하되, 없는 포장선·가려진 기단 등은 생략 사유와 불확실을 적는다. 실제로 관찰하지 않은 좌표나 선을 추정해서 채우지 않는다.

수동 화면 각도는 필요한 경우 `atan2(dy, dx)` 등 사용 방법, 점 선택/리사이즈 여부와 예상 판독 오차를 함께 기록한다. 확대본을 썼다면 원본 좌표로 환산한다. 화면 각도 차이는 투영 대조의 보조 증거이며 실제 3D 회전각이 아니다. 명백한 선군 모순과 수동 판독 오차를 구분하고, 한 사례의 각도·픽셀 길이·비율을 공통 허용오차로 고정하지 않는다. 증거가 약하거나 중요한 부분이 가려졌으면 UNCERTAIN이다.

- 3D 치수/콜라이더 미검증은 눈에 보이는 차단/비틀림을 면제하지 않는다. 적용 항목을 NOT_REVIEWED로 남겨 놓고 최종 구조 통과로 보고하지 않는다.

## 상태
- `candidate_pass`: 관찰 가능한 필수 기준에서 문제가 발견되지 않은 후보. 사용자 승인 아님.
- `needs_revision`: 기준 누락/실패 있음.
- `uncertain`: 핵심이 가려져 판단 어려움.
- `not_reviewed`: 실제 결과를 보지 못했음.
- `user_approved`: 사용자가 승인한 범위를 별도로 명시했을 때만.

## 실패에 따른 대응
구도/단면이 완전히 틀리면 실패 이미지 보존 편집에 집착하지 말고 01·02를 기반으로 재구성한다.
공간은 맞고 표면만 과밀하면 구도를 유지하며 밀도를 수정한다.
출구 한 곳만 누락됐으면 주변 경계만 수정하고 다른 공간/스타일의 변형 여부를 다시 본다.
생성/편집 요청의 구조 오류(C01~C04, L01~L07)는 사용자 상시 승인과 v2.3 검사 범위, master_update_20260910_v2_4의 최종 증거 및 master_update_20260911_v2_5의 필수 정사영 절차에 따라 수정·재생성하고 실제 이미지로 재검수한다. 최종 전달 장수는 유지한다. 전체 베이스/공통 투영 오류는 실패 기하를 보존하지 않고 원본01·02의 공간 틀로 재구성한다. 구조 통과 후 중단하며 도구 장애/관찰 불가/진전 없는 반복의 중단 기준은 docs/05_GENERATION_RULES.md를 따른다. 스타일 취향만으로 추가 변형을 만들지 않는다. 분석/검토/마스터 갱신 요청에서는 이미지 생성이 시작되지 않는다.

## 승인 기록
`state/approvals.json`에 사용자 발언과 승인 범위를 함께 남긴다.
“색감 마음에 들어”는 color 승인일 뿐 layout/material/overall 승인이 아니다.
`review_only/`는 실패/부분 승인 이력이다. Codex 자체 QA로 원본 마스터를 교체하지 않는다.

사용자가 테스트 결과의 마스터 추가·갱신을 명시하면 `docs/10_CURRENT_REFERENCES.md`의 절차로 승인한 범위만 반영한다. QA 통과나 단순 선호와 영구 기준 갱신을 구분한다. 명확한 갱신 요청에 불필요한 재확인을 요구하지 않는다.

## 재검토 이력과 실패 사례
새 검토는 대상 run·이미지와 이전 검토를 연결한 별도 기록에 판정/근거와 대체하는 범위를 남긴다. 원본 이미지와 과거 review/result는 당시 이력으로 보존한다. 최신 재검토가 needs_revision이면 이전 candidate_pass를 현재 합격으로 계속 인용하거나 그 결과를 양성 마스터/기본 이미지 입력으로 사용하지 않는다.
