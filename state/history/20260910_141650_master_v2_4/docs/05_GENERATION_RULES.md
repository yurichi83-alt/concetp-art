# Generation Execution Rules v1.4

> 기준 관계: 마스터 01~04 v2.3와 원본 19장+승인된 LDI 보강 5장(총24장)이 기준이다. Little Devil Inside 아트 표현(세계관 제외)과 Salvage Cyberpunk 세계관은 고정한다. A-01/A-02는 선호 예시이며 마스터를 대체하지 않는다. 상세: `docs/10_CURRENT_REFERENCES.md`.

## 0. 이 워크플로의 범위
이 프로젝트의 짧은 장소/시간/소재 요청은 실제 **배경 이미지 생성** 요청이다.
이미지 생성 앱을 만들거나 글 프롬프트만 제공하고 끝내지 않는다.
`검수만`, `기준 보여줘`, `파일 정리`는 생성 요청이 아니다. 분석/보강안 정리/마스터 갱신에서도 구조 오류를 발견했다는 이유로 자동 생성하지 않는다.
상위 시스템·호스트·도구의 실제 계약을 지키며 여기에 없는 API 옵션을 지어내지 않는다.

## 1. 변경분 해석
`docs/08_COMMANDS.md`에 따라 장소·시간대·색·소재·장수를 파악한다.
사용자가 말하지 않은 필수 공간/스타일 조건은 유지한다. 예외는 이번 장면과 영구 변경을 구분한다.
미정 장면 세부는 마스터에 맞게 선택하고 기록한다. 사소한 미정 요소마다 질문하지 않는다.
새 장소는 현재 장소의 기능·건축 매스·배치·포장·기반 시설을 설계한다. 직전 장면의 밤·안개·쓰레기·전봇대·좁은 공간과 건물/단면 모양을 자동 계승하지 않는다. 명시적인 기존 이미지 편집에서는 요청한 보존 범위만 고정한다.
장소 이름과 무관하게 04의 쇠락·회수·수리 세계를 적용하고 03의 넓고 정돈된 면으로 표현한다. 장면 계획에서 낡은 부분과 고쳐 쓰는 기능의 관계를 설명한다.

## 2. 원본 준비
`refs/manifest.json`의 역할을 확인하고 해당 이미지를 실제로 열어 본다.
마스터 자료는 원본19장+승인된 LDI 보강5장으로 총24장이다. 모두를 한 번에 첨부하지 않고 현재 도구의 입력 한도에 맞춰 선택한다.
- 새 장소의 기본 역할: M02-01 공통 바닥/직교 경계/연속 통로, M01-01 공통 투영/기본 입체/상하 대응/구도·단면, M03-10 대표 건축 표현, M04-02/04 등 세계관 형태. 같은 건축·문틀·배관 배치 복제를 지시하지 않는다.
- 추가 스타일은 장면에 맞춰 M03-11~15 또는 기존 보조 원본에서 선택한다. 예를 들어 입력5장이 가능하면 위 네 역할에 적합한 LDI 보강1장을 더할 수 있다. 실제 한도는 매 도구 계약으로 확인한다.
- M03-11~15는 건축·재질·조명/색만 사용한다. M03-12는 건물 부분만 참고하고 나무·풀·숲·자연 지면 제외. 03의 게임 세계·인물·카메라·UI를 복사하지 않는다.
- M04 이미지의 캐릭터, 실사 재질 밀도는 복사하지 않고 회수 기술의 큰 기능적 형태를 환경에 번역한다. 비슷한 스타일 사진이나 이전 결과를 여러 장 넣느라 M04 원본이 반복해서 빠지지 않도록 우선순위를 잡는다.
- 이미지 편집은 편집 대상도 입력 한도에 포함한다. 대상이 이미 보존할 공간을 담고 있다면 필요한 보정 원본과 스타일/세계관 자료를 골라 쓰며, 선택·생략 이유를 기록한다.
- 더 작은 한도에서는 공간과 아트 표현의 필수 역할을 우선하고 생략된 세계관 원본의 디자인 언어를 텍스트로 정확히 유지한다. 생략한 이미지를 전달했다고 기록하지 않는다.
- A-01/A-02는 종속된 선호 결과 예시다. 다른 생성 결과의 부분 선호는 docs/10_CURRENT_REFERENCES.md의 승인 속성만 비교하며 새 장소의 기본 입력으로 자동 사용하지 않는다. 기계 비중의 선호를 참고할 때도 장치·건물·단면의 원래 디자인을 복제하지 않는다.

**실제 참조 전달:** 도구가 파일/이미지 인자를 받으면 그 스키마에 맞게 파일을 전달한다.
현재 대화의 이미지만 받는 환경이면 그 환경이 지원하는 첨부/시각 컨텍스트 방식으로 원본을 제공한다.
경로를 프롬프트 문장에 쓰거나 Codex가 이미지를 열어 본 것과 이미지 모델에 전달된 것은 다르다.
전달할 수 없으면 파일 기반 참조가 불가능함을 알리고, 핵심 이미지를 첨부하는 등 지원되는 방법을 요청한다.
파일 전달이 안 되는데 몰래 텍스트 전용으로 같은 결과가 보장되는 것처럼 진행하지 않는다.
`review_only/`는 기본 입력 금지. 웹에서 임의의 대체 이미지를 찾아 마스터를 바꾸지 않는다.

## 3. 도구 확인과 비용 범위
세션에서 사용 가능한 내장 이미지 생성 또는 공식 imagegen 스킬의 설명을 먼저 확인한다.
내장 기능 우선. 별도 API 경로만 있으면 비용·키 필요 여부를 설명하고 사용자의 동의를 받은 후 사용한다.
기존 환경에 API 키가 있어도 그 존재만으로 사용 동의로 취급하지 않는다. 키를 출력·기록하지 않는다.
API 모델명·버전·가격은 하드코딩하지 않는다. 전역 설정·플러그인 설치·추가 구매를 임의로 하지 않는다.
기능이 없으면 프롬프트/준비 상태를 저장하고 장애를 보고한다. 생성했다고 말하지 않는다.

## 3a. 구조안부터 최종 대조까지 — v1.4

1. **기준 공간 준비:** 장면마다 기본 블록, 하나의 카메라, 두 경계와 기능 출구, 빈 통로 및 건물 부피를 같은 좌표로 잡은 단순 구조안을 먼저 만든다. 건물의 수평 외곽선과 높이/지붕 면을 분리해 기록한다. 기존 렌더러/카메라를 재사용해도 개별 출구 위치와 형태를 자동 상속하지 않으며, 현재 배치가 통로를 침범하지 않는지 확인한다.
2. **형태 검증:** 건물의 바닥 점유 외곽선과 플레이어 이동 공간에 접하는 고정 외벽의 각 선분이 공통 X/Y축에 평행한지 검사한다. 사선 절단·회전 건물·쐐기형 틈·곡선 건물 경계는 사용하지 않고 L/T/U형 및 직각 후퇴/돌출로 다양화한다. 지붕은 별도 면으로 정의하여 경사 시작/끝, 용마루/골/처마, 벽 상단과 장비 지지를 확인한다. 상·하단 대응과 통로 보호 부피의 겹침도 검사한다. 단순 경계상자(AABB) 충돌 없음만으로 직교 외곽선과 지붕 면 정합을 통과시키지 않는다.
3. **아트 적용:** 구조가 정리된 안내 이미지와 원본01·02를 구조 근거로 사용하고 03·04를 아트/세계관에 적용한다. 사용 가능한 이미지 입력 형식/개수를 확인해 실제 전달하고 역할을 기록한다. 글로 “틀리지 않게”만 지시하고 보장을 주장하지 않는다.
4. **최종 재검사:** 생성 모델이 구조 안내를 바꿀 수 있으므로 결과의 기본 모서리/주요 선군, 건물 직교 경계, 지붕 면 접합/장비 지지와 출구 상태별 통로를 다시 대조한다. 구조안이 맞았다는 사실이나 비정형을 의도했다는 설명을 최종 결과의 PASS 근거로 대체하지 않는다. 연결 구조를 확인할 수 없으면 UNCERTAIN, 명백한 모순은 FAIL이다.
5. **국소/전체 오류 분리:** 작은 출구 장애물은 해당 부분 편집. 베이스·바닥·여러 건물의 원근이 함께 어긋나면 전체 공간을 재구성. 단순 줌아웃으로 기하가 수정됐다고 판단하지 않는다.

이 절차는 오류 없는 출력 자체를 보장한다는 뜻이 아니다. **구조가 틀린 결과를 최종 합격으로 전달하지 않도록 하는 기준**이다. 생성/편집 기능의 한계로 확인이나 수정이 안 되면 검수 한계를 명시하며 PASS로 바꾸지 않는다.

검토용 설명 도식은 양성 마스터로 자동 등록하지 않는다. 참고 안내 파일은 실제 도구의 지원 형식으로 준비하며 SVG 지원이나 실제 전달을 추정하지 않는다.

직교 제한은 건물의 실제 수평 평면에 적용하며 화면에서 쿼터뷰 벽이 사선으로 투영되는 것은 정상이다. 소품·프랍·차량·원통 탱크의 외형과 회전은 이 제한 대상이 아니다. 이들도 공통 카메라·접지·두 방향의 차단 역할·보행 통로 보존은 지킨다. 건물 형태는 직교 매스/상층 후퇴/층별 높이와 경사·박공·톱니형·배럴형 지붕 등으로 변화시킨다. 지붕 경사가 건물의 사선 보행 경계를 허용하는 예외는 아니다.

## 4. 실제 생성 사양
- 한 결과당 단독 장면 하나. 요청 2장이면 파일 2개. 분할 화면/비교 시트는 사용자가 원할 때만.
- 정육면체형 공통 공간/정사각형 기본 평면과 하나의 투영을 사용한다. 전체 베이스·상하 대응 모서리·두 평면 단면·연결 경계를 사선 하이앵글로 프레이밍한다.
- 뒤쪽 좌측(약11시)·우측(약1시) 경계 방향에 기능 출구 한 개씩, 정확히 두 개를 식별 가능하게 설계한다. 각 면의 중앙·중간·끝과 대칭·비대칭을 허용한다. 도해나 이전 결과의 위치 복제도, 매번 위치를 바꾸는 순환 규칙도 강제하지 않는다.
- 출구는 클리어 후 다음 공간으로 이동하는 지점이다. 건물 입구/내부 전환, 건물 사이 골목과 개폐 철문, 시설 통로, 계단, 지하 주차장 램프 등으로 만들 수 있으며 독립된 문틀/열린 게이트를 강제하지 않는다. 역할·개폐 상태·접근 공간·개방 여유와 클리어 후 연결을 계획한다. 의도된 닫힌 철문은 잔해로 막힌 출구와 구분한다.
- 중앙부터 두 기능 출구의 전환 지점까지 폭·높이·회전 여유를 확보한다. 열린 상태는 보이는 연결 동선을 비우고, 닫힌 상태는 접근부와 개방 후 통로 및 문짝/셔터의 이동 여유를 확보한다. 건물 내부 전환의 모든 내부를 억지로 노출할 필요는 없지만 입구 규모와 연결이 읽혀야 한다. 노출 내부 시설에는 실체적 방 깊이와 내부 동선을 확보한다. 바깥 물체도 해당 보호 공간에 침범하지 않는다.
- 계단/램프는 높이 변화이며 평면 진행 방향과 건물 경계는 X/Y축을 따른다. 지정된 후방 출구로 지하 진입이 가능하나 전면 토층 절개면을 제3의 출구로 만들지 않는다. 건물 외에 펜스·컨테이너·탱크·차량/트럭·설비·지형 등으로 두 차단 방향을 구성할 수 있다. 물체 사이 틈은 의도하지 않은 제3의 이동 통로로 읽히지 않게 한다.
- 모델링 큰 면, 선택적 손상, 저밀도 3D 재질. “high quality”를 “high detail”로 자동 확장하지 않는다.
- 04의 회수·개조 첨단기술 적용. 03의 세계관이나 01의 네온 테마는 복사하지 않는다.
- 글자·번호·슬로건·화살표·UI는 요청 없으면 추가하지 않는다. 간판이 필요하면 제한적으로 사용한다.
- 인물/몬스터는 요청이 없는 배경 시안에 자동 삽입하지 않는다.
- 장식이 공간 규칙과 충돌하면 장식을 줄인다. 카메라·출구·단면·중앙을 생략하지 않는다.

작업용 화면 비율은 원본처럼 전체 베이스가 읽히는 비율을 고른다(예: 4:3 또는 1:1).
지원하지 않는 픽셀 옵션을 가정하지 않는다. 비율은 제안된 출력 선택이며 마스터의 고정 치수가 아니다.

## 5. 생성 전 기록
`outputs/<local_timestamp>_<scene_slug>/`를 고유하게 만든다(기존 폴더 덮어쓰기 금지).
- `brief.md`: 장면 해석, 마스터 버전, 신규/편집 구분, 구조 계획, 장소별 건축/단면 설계, 노후·회수 기술의 기능, 사용자 원문, 컴파일한 아트 지시. 기능 출구마다 방향·면 안 위치·형태·현재 개폐 상태·클리어 후 연결·개방 여유·건물 입구 겸용 여부를 기록한다. 표시용 번호/화살표를 이미지에 삽입하지 않는다.
- `references.json`: 검토 자료와 실제 전달 자료, 역할/제외 범위, 원본 경로와 입력 순서/전달 상태, 생략 이유와 부분 선호의 승인 범위.
- `preflight.md`: 필수 조건이 계획에 포함되는지, 도구·파일 접근·요청 장수 확인.
이 브리프는 **의도한 생성 지시의 기록**이지 비공개 내부 프롬프트 원문을 확보했다는 뜻이 아니다.

## 6. 호출과 저장
요청 장수는 최종 전달할 장수다. 사용자가 2026-09-09에 승인한 구조 오류 자동 보정에 따라, 실제 검수에서 구조 오류가 발견되면 재확인 없이 수정·재생성한다.
- 대상: C01~C04, L01~L07. 프레이밍/단면·기본 입체·공통 투영·경계/기능 출구·접지·중앙/출구 및 해당 내부 동선·건물 직교 경계. 지붕 면 접합과 장비 지지는 C04/L05에서 확인한다. 검사 구체화 및 L07 반영 승인: master_update_20260910_v2_3. 분석/검토/마스터 갱신 요청은 자동 생성 대상이 아니다.
- 수정 전에 실제 오류와 유지할 요소를 기록한다. 바닥 연결이나 건물 배치 자체가 잘못되면 기존 이미지를 그대로 보존하려 하지 말고 M01/M02에 맞춰 재구성한다.
- 매 결과를 실제로 열어 구조안과 대조한다. 해당 구조 항목 전부 PASS이고 적절한 N/A 근거가 있을 때 구조 통과로 전달한다. 구조 FAIL은 전체 needs_revision, 핵심 불확실은 uncertain이다. 통과 후 추가 변형을 중단한다.
- 자동 보정 이력은 각각 고유 run에 입력·지시·결과·검수와 이전 run 연결을 보존한다. 잘못된 결과는 삭제/덮어쓰지 않는다.
- 스타일·색·손상 밀도에 대한 취향 차이만으로 자동 변형을 늘리지 않는다. 구조 보정 중 기존 아트/세계관/현재 키워드는 유지한다.
- 관찰 불가, 도구 오류/한도, 별도 과금 API·설치·권한 확대 필요, 사용자의 중지, 또는 동일 오류가 반복되고 새로운 수정 전략도 없는 상황에서는 추가 호출을 멈추고 상태를 설명한다. 같은 지시를 무작정 반복하지 않는다.
- 이 승인은 프로젝트 내 내장 도구의 구조 수정에 한정된다. 별도 API·설치·전역 설정·마스터 자동 승격 권한은 포함하지 않는다.
도구 반환의 실제 파일/아티팩트에 접근 가능하면 원본 형식 그대로 같은 run에 저장한다.
PNG가 아닌 파일을 확장자만 PNG로 바꾸지 않는다. 존재하지 않는 경로/다운로드 링크를 만들지 않는다.
도구가 결과를 UI에만 제공하면 그 사실과 접근 가능 범위를 기록한다. 결과 복사는 다음 턴에 가능할 수 있다.
이미지 생성 후 즉시 응답을 종료해야 하는 호스트에서는 그 규칙을 따르고, 저장/QA는 다음 턴에 진행한다.

## 7. QA와 전달
실제 결과를 열 수 있는 경우 `docs/06_QA.md`의 기준으로 관찰하고 `review.md`에 기록한다.
열 수 없거나 후처리가 막혔으면 `not_reviewed`. 정확한 높이는 `requires_3d_validation`.
결과를 전달하되 결함을 숨기지 않는다. 구조, 아트/세계관, 장면 키워드를 나누어 보고 검수 합격과 사용자 승인을 구분한다. 새 장소는 조명과 색을 제외해도 건축·공간·단면의 차이가 읽히는지 확인한다. 의도적인 고저차나 계단은 연결·접지와 건물 직교 경계가 타당하면 구조 오류로 취급하지 않는다.
구조 오류는 위의 상시 승인에 따라 실패한 부분과 유지 부분을 나눠 다음 run에서 수정한다. 구조 외 추가 생성은 현재 사용자 요청 범위를 따른다.
사용자 승인 없이는 master·refs·approved ledger를 성공 결과에 맞춰 바꾸지 않는다.

## 구조 기록과 판정
장면 구조안은 같은 좌표의 기본 블록·카메라·경계/기능 출구·건물 수평 외곽선과 선분별 축·높이/지붕 면·건물 및 소품 부피·보행 보호 공간을 담아 outputs의 해당 run에 structure_plan.*로 저장한다. 출구 두 개 각각의 방향·면 안 위치·형태·현재 상태·클리어 후 연결·개방 여유·건물 입구 겸용 여부도 포함한다. 브리프에는 투영, 경사면/벽 상단/기계 지지의 연결, 통로의 최소 구간/회전부/전환부 및 상태별 개방 후 연결을 기록한다. 출구가 건물 내부 전환이면 관찰 가능한 입구와 계획된 연결을 구분한다. 경계상자 겹침 검사로 외곽선/지붕 검사를 대체하지 않는다.

검사 순서는 기본 입체 → 공통 투영/지붕 면 정합 → 건물 직교 경계 → 바닥/경계 연결 → 두 기능 출구의 상태별 동선 → 해당 내부 동선 → 아트/세계관/요청 사항이다. C01~C04·L01~L07 중 하나라도 FAIL이면 전체 결과는 needs_revision이고, 핵심을 확인할 수 없으면 uncertain이다. 분위기·소품·세계관이나 의도된 비정형이라는 설명이 구조 실패를 상쇄하지 못한다. 베이스나 공통 원근이 잘못되면 실패 이미지의 기하를 보존하는 편집을 중단하고 원본01·02의 공간 틀로 재구성한다. 사용자 요청이 분석/검토/마스터 갱신인 경우에는 자동 재생성하지 않는다.

## 건축 외관 계획·검수 보완 — 2026-09-10
