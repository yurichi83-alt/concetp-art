# 결과 검수와 승인

> 기준 관계: 마스터 01~04 v2.2와 원본 19장+승인된 LDI 보강 5장(총24장)이 기준이다. Little Devil Inside 아트 표현(세계관 제외)과 Salvage Cyberpunk 세계관은 고정한다. A-01/A-02는 선호 예시이며 마스터를 대체하지 않는다. 상세: `docs/10_CURRENT_REFERENCES.md`.

원본 마스터 적합성을 먼저 검수하고 A-01/A-02의 선호 결과 인상도 함께 비교한다. 선호 예시를 원본 마스터의 대체 기준으로 삼지 않으며, 디테일 개수만으로 기계적으로 판정하지 않는다.

## 검사 순서
기본 입체 → 공통 투영 → 바닥/경계 접합 → 두 외부 통로 → 해당 내부 동선 → 스타일 → 세계관 → 개별 요청.
실제 이미지에서 관찰한 근거를 기록한다. 프롬프트에 들어 있으므로 PASS라고 판단하지 않는다.
이미지를 열 수 없으면 `NOT_REVIEWED`; 애매하면 `UNCERTAIN`으로 남긴다.

| ID | 확인 항목 | FAIL 예시 |
|---|---|---|
| C01 | 단독 쿼터뷰·전체 프레이밍·독립성 | 베이스/연결 경계 크롭, 붙어 있는 잘린 벽을 배경 예외로 취급 |
| C02 | 양면 단면의 존재와 두께/모서리 대응 | 단면이 보여도 상하 대응·평면 접합이 틀림 |
| C03 | 기본 블록 기하 | 기준면 비틀림, 대응 수직 모서리 불일치, 요청하지 않은 곡률/모따기/추가 꼭짓점 |
| C04 | 공통 카메라·투영 | X/Y/Z 선군과 기초·외벽·포장·출구의 투영 불일치, 회전과 원근 오류 혼동 |
| L01 | 공통 바닥 위의 인접한 두 직교 경계 | 기본 입체와 어긋난 경계/접합, 제3의 틈 |
| L02 | 좌우 각 하나의 외부 출구와 전후 바닥 | 문틀만 보임, 한쪽 누락, 문턱 너머 차단/단절, 제3의 외부 통로 |
| L03 | 중앙부터 두 출구 너머까지 연속 보행 부피 | 시작부/최소 폭/회전부/문턱 전후에 상자·잔해·난간·장치·문짝 침범, 가는 빈 선만 존재 |
| L04 | 전면 시야 확보 | 높은 전면 물체가 전투장/단면을 가림 |
| L05 | 기준면·건물 기초·외벽·문턱의 접합/지지 | 높이/축/투영의 모순, 근거 없는 바닥 비틀림/단절 |
| L06 | 해당하는 내부 시설의 이동 공간 | 입구→통로→기능 영역 차단, 외관 대비 얕은 진열 상자. 내부 미노출/미해당은 N/A |
| S01 | 큰 형태와 기본 색면 보존 | 벽/차량/지면 전반의 촘촘한 손상 |
| S02 | 구조·표면·배치 밀도 균형 | 부품과 쓰레기가 화면 전체에 같은 밀도 |
| S03 | 게임 3D 표현 | 붓질, 초정밀 모형 사진, 과한 각진 로우폴리/플라스틱화 |
| W01 | 기능이 읽히는 수리·재사용 첨단기술 | 일반 산업 설비/장식 표시등만 있고 회수·수리 기능 관계가 없음 |
| W02 | 장소 전반의 쇠락과 유지 흔적 | 신품 건축에 SF 장치만 붙임, 미세 오염만 있고 수리/재사용 이력 없음 |
| W03 | 건축 대비 기계의 존재감 | 단면에만 기술 집중, 건물 규모에 묻힘, 부품 수만 늘어나거나 모든 사물을 무조건 기계화 |
| S04 | 후속 설계를 위한 형태 가독성 | 부피·두께·접지·기계 결합이 불명확하거나 표면 무늬로 구조를 대신함 |
| R01 | 장소·시간·소재·장수 | 현재 요청 누락, 이전 장면의 소재·안개·날씨를 무조건 계승 |
| R02 | 새 장소의 건축·공간·단면 차이 | 장소가 바뀌었는데 이전 건물·문틀·포장·단면을 거의 그대로 두고 색과 빛만 변경 |

S01은 넓은 면의 정돈 여부를 보고 건물의 신품 여부와 분리한다. W02는 큰 파손·보수·교체·우회 공급 등 실제 환경의 흔적으로 확인한다. W03은 승인된 낮 골목 보강 시안의 기계 비중을 필요한 경우 비교하되 수치 비율이나 장치 복제를 요구하지 않는다. R02는 새 장소 요청에 적용하고 기존 장면의 명시적 편집에는 NOT_APPLICABLE로 기록한다. 개별 변경 개수를 강제하지 않고 장소로서의 차이를 근거로 판단한다.

고저차·계단·의도적인 건축 방향 변화는 동선과 접지가 명확하면 오류가 아니다. 원본02의 연결 조건을 동일 건물 두 줄이나 단일 높이의 평면으로 축소하지 않는다.

높이 약 6.5m, 정확한 통로 폭, 실제 플레이어/콜라이더 통과는 3D 치수 검사 대상이다.
이미지 검수에서 수치 적합으로 단정하지 않는다. S04도 3면도 정합·AI 메시 품질·UV/재질맵 검증을 뜻하지 않는다. 계획 의도와 확실히 과도한 높이 여부만 기록한다.
출구 수 또한 관찰 기반이며 가려지거나 애매하면 정확히 두 개라고 확정하지 않는다.

## v2.2 필수 구조 판정
검사 순서는 기본 입체 → 공통 투영 → 바닥/경계 연결 → 두 외부 통로 → 내부 동선 → 아트/세계관/요청 사항이다. 공간 항목 하나라도 FAIL이면 전체 결과는 needs_revision이고, 핵심을 확인할 수 없으면 uncertain이다. 분위기·소품·세계관이 잘 나와도 구조 실패를 상쇄하지 못한다. 베이스나 공통 원근이 잘못되면 실패 이미지의 기하를 보존하는 편집을 중단하고 원본01·02의 공간 틀로 재구성한다. 사용자 요청이 분석/검토만인 경우에는 자동 재생성하지 않는다.

- C01 프레이밍은 C03 기본 기하/C04 투영을 대신하지 않는다. C02도 흙/배관의 존재만으로 통과하지 않는다.
- L03은 좌/우 각각 시작부·최소 폭·회전부·문턱·문턱 너머를 기록하고 물체의 부피 침범을 검사한다.
- L06은 해당 실내를 보이는 경우 적용하고 미해당은 N/A 근거를 기록한다.
- 모든 적용 구조 항목이 PASS여야 통과한다. 구조 FAIL 하나는 전체 needs_revision이며 핵심 불확실은 uncertain이다.
- 정투영의 평행선과 투시의 방향별 소실점/공통 지평선을 구분한다. 계획된 회전도 같은 카메라를 따라야 한다.
- 3D 치수/콜라이더 미검증은 눈에 보이는 차단/비틀림의 면제 사유가 아니다.

## 상태
- `candidate_pass`: 관찰 가능한 필수 기준에서 문제가 발견되지 않은 후보. 사용자 승인 아님.
- `needs_revision`: 기준 누락/실패 있음.
- `uncertain`: 핵심이 가려져 판단 어려움.
- `not_reviewed`: 실제 결과를 보지 못했음.
- `user_approved`: 사용자가 승인한 범위를 별도로 명시했을 때만.

## 실패에 따른 대응
구도/단면이 완전히 틀리면 실패 이미지 보존 편집에 집착하지 말고 01·02를 기반으로 재구성한다.
공간은 맞고 표면만 과밀하면 구도를 유지하며 밀도를 수정한다.
출구 한 곳만 누락됐으면 주변 경계만 수정하고 다른 공간/스타일의 변형 여부를 다시 본다.
구조 오류(C01~C04, L01~L06)는 사용자 상시 승인에 따라 수정·재생성하고 실제 이미지로 재검수한다. 최종 전달 장수는 유지한다. 구조 통과 후 중단하며 도구 장애/관찰 불가/진전 없는 반복의 중단 기준은 docs/05_GENERATION_RULES.md를 따른다. 스타일 취향만으로 추가 변형을 만들지 않는다.

## 승인 기록
`state/approvals.json`에 사용자 발언과 승인 범위를 함께 남긴다.
“색감 마음에 들어”는 color 승인일 뿐 layout/material/overall 승인이 아니다.
`review_only/`는 실패/부분 승인 이력이다. Codex 자체 QA로 원본 마스터를 교체하지 않는다.

사용자가 테스트 결과의 마스터 추가·갱신을 명시하면 `docs/10_CURRENT_REFERENCES.md`의 절차로 승인한 범위만 반영한다. QA 통과나 단순 선호와 영구 기준 갱신을 구분한다. 명확한 갱신 요청에 불필요한 재확인을 요구하지 않는다.
