# Game Environment Art

로컬 아트 기준을 현재 내장 이미지 도구에 적용한다. 독립 이미지 엔진이나 API 클라이언트가 아니다.

## 기준 확인
이 파일에서 위로 찾아 AGENTS.md·project.json이 있는 루트를 확인한다. 새 세션/문서 변경 후 docs/00_INDEX.md, 마스터01~04, docs/05_GENERATION_RULES.md, docs/06_QA.md, docs/10_CURRENT_REFERENCES.md를 읽는다. 매 요청 직전 현재 사용자 지시·project.json·refs/manifest.json·state/approvals.json을 확인한다. 실행 세부는05, 판정은06, 참조 범위는10이 담당한다. 전문을 생성 프롬프트에 복사하거나 같은 기준을 여러 기록의 별도 현재값으로 관리하지 않는다.

## 장면 실행
1. docs/08_COMMANDS.md로 새 장소·독립 시안·편집·검수 요청을 구분한다. 새 장소는 공간 불변 조건 안에서 건축·배치·포장·단면을 다시 설계하며 직전 소품·날씨를 자동 누적하지 않는다. 편집은 실제 지정 대상을 확인하고 보존 범위를 정한다. 현재 대화에서 계속 유효한 사용자 지시는 유지한다. 분석/검수/마스터 갱신은 이미지 생성 허가가 아니다.
2. 현재 내장 이미지 도구와 공식 imagegen 스킬의 실제 계약을 확인한다. 도구가 제공하지 않은 인자·한도·가중치·마스크를 가정하지 않는다. 최근 이미지 선택의5장 상한은 경로 입력 상한의 근거가 아니다. 반환되지 않은 모델명·토큰·내부 수정 프롬프트는 미확인으로 남긴다.
3. 단일 정사영(orthographic)·공통 XYZ/척도·정사각형 베이스와 두 전면 단면·두 후방 기능 출구·보행 보호 공간을 구조안에 기록한다. 건물 직선축과 허용된 지상 곡면을 구분하고 기단/상하 대응의 가시성을 확보한다. 큰 형태→외벽/기능 공간 깊이→표면 순서로 설계하며 가이드에도 층수뿐 아니라 하우징·리세스·지지·데크 같은 기능 부피와 접합을 남긴다. 특정 형태·층수·비율·소품을 전역 기본값으로 만들지 않는다.
4. 역할별 참조를 실제로 열고 도구 계약에 맞게 전달한다. 01/02는 구조·공간,03은 LDI 건축·재질·빛·색,04는 Salvage Cyberpunk의 회수·수리 기능을 맡으며 스타일 원근을 복사하지 않는다. 마스터27장과 M03-10의 대표 역할을 유지한다. M03-11~15와 M03-12 건물만 범위, A 선호 예시의 종속 역할을 지킨다. B03-01은 선택 표면 입력, B03-02~04는 표면 비교 전용, F-01~07은 선택 형태 입력, F-08~11은 형태 비교 전용이며 각각 별도 분류와 기하 미승인을 유지한다. 상세는10을 따른다. 보정에서도 아트·세계관 입력 전부 제거를 기본 해법으로 쓰지 않는다.
5. templates/brief.md·preflight.md·references.json·generation_prompt.md와 templates/requirements.json을 사용한다. run의 requirements.json을 단일 원장으로 삼아 각 요건의 원문/마스터 출처·긍정/금지/후퇴 조건·정확한 실제 프롬프트 구절·담당 참조·관찰 영역/근거·판정을 연결한다. STRUCTURE/ART 같은 구역명만으로 대응을 끝내지 않는다. 실제 프롬프트는 구조 필수→현재 장면→아트/참조 역할 순서로 작성하며 문장 길이 자체를 목표로 삼지 않는다.
6. 실제 호출 문자열·이미지 인자/경로/수·역할·확인된 계약을 기록하고, python3 scripts/validate_run.py --run outputs/<run> --stage preflight로 기록 연결을 검사한 뒤 요청한 최종 장수를 생성한다. 독립 시안은 각각 마스터에서 출발하며 서로의 생성물을 입력하지 않는다. 시안 자신의 보정은 별도 run에 연결한다. 이전 run의 값에 정정을 덧붙이지 말고 이번 run의 단일 현재값을 기록한다.
7. 실제 최종 원본을 열어 전체와 원본 해상도 확대를 모두 검사한다. 구조·아트/표면·요청/수정 전후 보존 역할을 독립적으로 나누며, 가능하면 하위 에이전트가 담당 기준과 원본부터 판단한다. 불가능하면 역할별 순차 검수와 그 방식을 기록한다. 아트 검수는 이전 PASS보다 참조와 결과를 먼저 본다. 표면별 긍정 붓터치와 금지 자국의 부재를 각각 확인하며 R03으로 보정 전후 기능 형태·깊이·표면·요청의 후퇴를 검사한다. 실제 관찰과 원장을 연결한 뒤 --stage review를 실행한다. 계획 충족·호출 성공·파일 검사 PASS는 시각 합격이 아니다.
8. master_update_20260912_v2_8_pipeline_quality에 따라 생성/편집 요청에서 관찰한 명시 마스터·사용자 요건의 C/L/S/W/R 실패는 재확인 없이 보정·재검수한다. 전체 기하 실패는01/02에서 재구성하되 유효한 기능 부피와 개성을 보존하고, 구조가 적합한 표면 실패는 대상 이미지를 편집한다. 변경 요인을 제한하고 원인 실험은 단일 변수·성공/실패 기준을 먼저 기록한다. 내장 편집의 픽셀 보존을 약속하지 않고 모든 필수 요건과 전후 후퇴를 다시 확인한다. 충족된 결과의 취향 변형은 자동으로 늘리지 않는다. 방법 선택과 중단 조건은05를 따른다.
9. 모든 적용 C/L/S/W/R·현재 필수 요건으로 후보를 비교하고 개선·유지·후퇴 및 선택 이유를 남긴다. 선택본의 상태·사유·해시·원본 경로를 outputs/final_manifest.json에 먼저 등록한 뒤 --stage selection을 실행하고 사본을 수집·검증한다. 최신 보정본을 자동 선택하거나 구조 개선으로 다른 필수 실패를 상쇄하지 않는다. 구조 통과는 부분 완료이며 모든 적용 필수 요건의 관찰 PASS와 미해당 사유가 있어야 전체 완료다. 보정 한계·관찰 불가·사용자 중지는 전체 완료와 구분한다. 전체 통과본이 없으면 전달 후보의 needs_revision/uncertain/not_reviewed 상태와 남은 요건을 공개한다.

## 표현·범위·이력 보존
Master03 본문v2.3의 넓고 깨끗한 기본 색면과 온전한 면에도 읽히는 크고 성긴 방향성 평면 붓터치를 유지한다. 녹·오염·박리만으로 대체하거나 붓질 자체를 금지하지 않는다. 큰 명암·일관된 빛·재질 차이를 유지하며 표면을 부조·물결/굴절 유리·반복 미세 자국·모자이크로 만들지 않는다. 큰 기능 부피를 되살린다는 이유로 미세 부품을 늘리지 않는다. LDI 세계관은 제외하고 Salvage Cyberpunk의 수리·재사용 기능을 현재 건축과 생활 설비에 연결한다.

건물의 입구와 건물별 윗면40~80%는 비건물에 확대하지 않으며 장면의 기계 비중과 구분한다. 실제 콜리전·메시·UV·치수 검증은 이미지의 합격 조건이 아니다. 이미지의 접지·두께·지지·경계·연결·동선은 계속 검사한다. 2D 가이드와 좌표 JSON은 강제3D 기하 제어가 아니며 이번 요청을3D 제작으로 바꾸지 않는다.

최종 전달본은 outputs/final_manifest.json에 원본·고유 이름·검수 상태·비교에 따른 선택 이유를 등록하고 python3 scripts/collect_final_images.py 및 --verify로 outputs/final/ 사본을 수집·검증한다. run 원본·실제 입력·실패/이전 검수와 사용자별 편집 전달본을 보존하며 자동 보정 중간본·참조·가이드·검수 확대본은 최종 모음에서 제외한다. 상세는 outputs/README.md를 따른다. 수집/검증은 시각 합격이나 마스터 승격이 아니다.

## 도구 경계
상위 지침과 실제 도구 계약이 우선이다. 별도 과금 API·설치·전역 설정·권한 확대는 승인 없이 하지 않는다. 도구 장애·관찰 불가·동일 실패 반복과 새 전략 부재에서는05의 중단 사유와 실제 결과를 기록한다. 검증되지 않은 참조 제거를 효과가 확인된 해법처럼 반복하지 않는다.

호스트가 생성 직후 종료를 요구하면 후처리를 다음 턴으로 미루고 보지 못한 결과는 not_reviewed로 남긴다. 기존 이미지/검수를 덮어쓰지 않고 새 재검토로 대체 범위를 기록한다. 실패 이미지의 유효한 형태는 해당 보존 비교에만 사용하며 양성 기하 마스터로 승격하지 않는다. 원본/승인 범위는 사용자 갱신 지시 없이 바꾸지 않는다.
